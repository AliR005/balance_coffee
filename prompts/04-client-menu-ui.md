# 04 · Клиент: старт, меню, экран напитка, заказ

Режим: сначала Plan, после OK — Build.
Прочитай `AGENTS.md`, `docs/SPEC.md` (C1–C4, правила 5.1–5.3), `docs/DESIGN.md` (разделы 6–9), `design/preview.html`, готовые компоненты из `web/src/shared/ui`.

## Цель
Клиент открывает приложение, выбирает точку, собирает напиток и добавляет его в заказ. Оформление делается в фазе 06.

## Что сделать
1. **Старт** (DESIGN 8.1): показывается один раз при первом запуске (флаг в localStorage), дальше приложение открывается сразу в меню.
2. **Точка:** пилюля в шапке меню с признаком «открыто до …» и списком точек. Выбор запоминается (Zustand persist). При смене точки с непустым заказом — подтверждение: меню и стоп-лист различаются.
3. **Меню** (DESIGN 8.2): шапка с `Wordmark` и иконкой заказа с точкой-счётчиком, заголовок, чипы категорий (липкие при прокрутке), сетка из двух колонок `MenuCard` с `Photo`. Данные из `GET /locations/{id}/menu` через TanStack Query. Скелетоны, пустое состояние, ошибка с кнопкой «Повторить». Стоп-лист: «Закончилось», карточка не нажимается. `BottomNav`: «Меню» и «Заказы».
4. **Экран напитка** (`/drink/:id`, DESIGN 8.3): фото на всю ширину, «назад», название, описание, цена, живая `DrinkCup` справа от цены, группы опций из данных API. Правило отображения: `max_select = 1` — `SizeCard` для размера и чипы для остальных; `max_select > 1` — мультивыбор чипов или `Stepper` (шот). Обязательные группы помечены, попытка добавить без выбора прокручивает к группе и подсвечивает её. Недоступные опции серые. Липкая кнопка «Добавить в заказ · цена ＋». Переход из карточки в экран напитка: shared layout фото.
5. **Предпросчёт цены:** чистая функция `computePrice(product, selection, qty)` в `web/src/features/menu/pricing.ts`, тот же алгоритм, что в SPEC 5.1. Тесты обязательны.
6. **Заказ (корзина):** Zustand с persist, привязка к `location_id`. Позиция хранит `product_id`, выбранные `option_id`, количество; названия и цены берутся из актуального меню при показе. После добавления: тост «Добавлено», иконка заказа подпрыгивает. Иконка ведёт на экран оформления (заглушка до фазы 06).
7. Тексты только через словарь i18n, по разделу 9 DESIGN.md.

## Тесты
`computePrice`: без опций, с опциями, отрицательная дельта, количество. Корзина: добавить, объединить одинаковые позиции, смена точки. Экран напитка: обязательная группа блокирует добавление.

## Границы (не делай)
Оформление, слоты, отправку заказа, статус, повтор заказа, PWA, экран баристы, бонусы, видео, избранное, лендинг.

## Критерии готовности
- Полный путь на телефоне 390 px: старт → точка → категория → напиток → состав → в заказ, без ошибок в консоли.
- Чашка и цена реагируют на каждый выбор мгновенно; с `prefers-reduced-motion` анимаций нет.
- Скелетоны и ошибки сети выглядят осмысленно (проверь, отключив бэкенд).
- Вид совпадает с `design/preview.html` (тёмная тема), светлая тема не ломается.
- `make lint` и `make test` зелёные.

Отчёт по формату из AGENTS.md. Приложи скриншоты трёх экранов, если можешь их сделать.
