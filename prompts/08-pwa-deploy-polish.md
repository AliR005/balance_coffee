# 08 · PWA, деплой, полировка

Режим: сначала Plan, после OK — Build.
Прочитай `AGENTS.md`, `docs/DESIGN.md` (разделы 5, 9, 10), `docs/SPEC.md` (раздел 7).

## Цель
Приложение ставится на экран телефона, живёт по публичному HTTPS-адресу и ощущается законченным.

## Что сделать
**PWA**
- `vite-plugin-pwa`: manifest (`name: Balance`, `theme_color` — медь, `background_color` — `--bg`), иконки 192/512 и maskable из `logo-b.svg` (белая b на меди; скрипт генерации PNG, например через sharp), `display: standalone`.
- Service worker кеширует оболочку и статику, но не API и не SSE. Офлайн: понятный экран «Нет связи. Пробуем снова». Обновление приложения без потери корзины.

**Деплой**
- `docker-compose.prod.yml`: Caddy (автоматический HTTPS), `api`, `db`, статика `web`. Caddy проксирует `/api` в `api` без буферизации SSE.
- `docs/DEPLOY.md`: пошагово, как поднять на VPS (домен, `.env`, миграции, seed, бэкап БД, обновление). Переменные окружения — только через `.env`, секретов в репозитории нет.
- CORS, заголовки безопасности, ограничение частоты запросов на `/staff/login` и `POST /orders`.

**Полировка**
- Скелетоны на всех загрузках, error boundary, единые пустые состояния и ошибки.
- Аудит тёмной темы на всех экранах. Аудит доступности (axe), фокус, области нажатия, контраст.
- Lighthouse на мобильном профиле: Performance и Accessibility ≥ 90. Разбор размера бандла, разделение по маршрутам.
- Проверка `prefers-reduced-motion`.
- Иконка приложения, favicon, `<title>`, meta для шаринга.

**E2E**
- Playwright: сквозной сценарий демо (клиент заказал → бариста принял → клиент увидел статус) как один автоматический тест.

## Границы (не делай)
Push-уведомления, онлайн-оплату, аналитику, новые фичи.

## Критерии готовности
- Открыл публичный URL на iPhone и Android → «Добавить на экран» → запускается как приложение с иконкой.
- Демо-сценарий проходит автоматическим тестом.
- `make lint`, `make test` и e2e зелёные; Lighthouse-показатели приложены к отчёту.
