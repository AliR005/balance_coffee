# 09 · Подготовка демо для клиента

Режим: сначала Plan, после OK — Build.
Прочитай `AGENTS.md`, `docs/SPEC.md` (разделы 1, 8, 9), `docs/DESIGN.md`.

## Цель
Демо, которое можно повторять без сюрпризов, и понятный рассказ о том, что будет в полной версии.

## Что сделать
1. **`make reset-demo`:** очищает заказы, слоты и счётчики, заново применяет seed, выводит PIN'ы баристы и ссылки (клиент, бариста, QR-код клиентской ссылки в терминале). Выполняется за секунды и безопасен для повторного запуска.
2. **Загрузка реального меню:** проверь, что `backend/seed/menu.yaml` содержит понятную структуру и комментарии, как заменить демо-данные данными клиента (напитки, цены, опции, точки, часы). Добавь валидацию seed с читаемыми ошибками. Опиши в `docs/DEMO.md`.
3. **`docs/DEMO.md`:**
   - сценарий на 5 минут по шагам (клиент на телефоне, бариста на планшете), что говорить на каждом;
   - чек-лист за час до показа (интернет, зарядка, PIN, стоп-лист для демонстрации, звук включён, приложение установлено на экран телефона);
   - запасной план, если нет сети или что-то упало (заранее записанное видео сценария, локальный запуск);
   - список вопросов клиенту из SPEC 9.
4. **`docs/ROADMAP.md`:** «Что будет в полной версии» для показа клиенту: онлайн-оплата, аккаунты и лояльность, админка меню с фото, push, заказ на другие дни, интеграция с кассой, аналитика. Для каждого пункта — 1–2 предложения о пользе для бизнеса, без технических терминов.
5. **Демо-данные:** в seed добавь опцию `demo: true` со стоп-листом, который показательно работает («Колд брю закончился» на одной точке).

## Границы (не делай)
Новые фичи и рефакторинг. Всё, что нашлось по дороге и не блокирует демо, записывай в `docs/BACKLOG.md`.

## Критерии готовности
- С чистого сервера: `make reset-demo` → сценарий из `docs/DEMO.md` проходится без ошибок.
- Второй человек по документации сможет провести демо, не спрашивая тебя.
