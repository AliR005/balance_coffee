# Balance — набор для старта с opencode

Здесь всё, чтобы начать: правила для агента, ТЗ, дизайн, готовые промпты по фазам.

```
AGENTS.md                 правила проекта; opencode читает его сам
docs/SPEC.md              ТЗ и бизнес-правила
docs/DESIGN.md            дизайн (тёмный, фото-центричный): идея, цвет, шрифт, движение, экраны, тексты
docs/BACKLOG.md           сюда агент пишет идеи «на потом»
design/tokens.css         дизайн-токены (единственный источник цветов и радиусов)
design/preview.html       живой макет всех экранов (открыть в браузере, есть переключатель темы)
design/assets/logo-b.svg  логотип-заглушка, заменить официальным
prompts/00…09, 06b        фазы работы (06b — бонусы)
prompts/_review.md        ревью после каждой фазы
prompts/_bugfix.md        шаблон для исправления багов
```

## Один раз: подготовка

1. Поставь git, Docker, Python 3.12+ с uv, Node 20+ с pnpm.
2. Поставь opencode (`npm i -g opencode-ai`, актуальные способы — на opencode.ai) и подключи провайдера моделей: `opencode auth login` или через меню провайдеров в самом интерфейсе.
3. Создай репозиторий и положи туда содержимое этого набора:

```bash
mkdir balance && cd balance
# распакуй сюда содержимое balance-kit так, чтобы AGENTS.md лежал в корне
git init && git add -A && git commit -m "docs: spec, design, prompts"
opencode        # запускай всегда из корня репозитория
```

Модель выбирается командой `/models`. Для планов и для фазы 05 бери самую сильную из доступных, для рутины можно быстрее и дешевле.

## Цикл на каждую фазу

1. `/new` — новая сессия, чистый контекст.
2. Нажми **Tab**, чтобы включить режим **Plan** (агент только читает и предлагает).
3. Отправь: `@prompts/01-scaffold.md выполни` (после `@` opencode подсказывает файлы).
4. Прочитай план. Проверь, не вышел ли он за «Границы» фазы. Поправь словами: «убери…», «сначала сделай…».
5. Нажми **Tab** ещё раз, режим **Build**. Напиши: «План принят, выполняй».
6. Когда закончит: сам запусти `make lint && make test`, посмотри `git diff`, пройди сценарий руками в браузере.
7. Ревью: `/new`, режим Plan, `@prompts/_review.md`. Согласуй исправления, включи Build.
8. Коммит (текст возьми из отчёта агента). Переходи к следующей фазе.

Начни с `@prompts/00-kickoff.md`: это разведка без кода, она покажет, как агент понял проект и есть ли пробелы.

## Порядок фаз

| Фаза | Результат | Оценка* |
|---|---|---|
| 00 | Агент понял проект, вопросы закрыты | 15 мин |
| 01 | Каркас: docker, API, фронт, токены, генерация клиента | 0,5–1 день |
| 02 | Меню, точки, seed, цена и валидация | 1–1,5 дня |
| 03 | Дизайн-система: компоненты, фото-заглушки, чашка-баланс, брызги | 1–2 дня |
| 04 | Клиент: старт, меню, экран напитка, заказ | 2–3 дня |
| 05 | Слоты, заказы, статусы, staff API, SSE | 2–3 дня |
| 06 | Оформление, «Мой заказ», повтор | 2 дня |
| 06b | Бонусы: начисление, списание, уровни, экран | 1–2 дня |
| 07 | Экран баристы и стоп-лист | 2 дня |
| 08 | PWA, деплой, полировка, e2e | 1–2 дня |
| 09 | Демо: `make reset-demo`, сценарий, дорожная карта | 0,5–1 день |

*Оценки грубые, для одного человека с агентом, включая ревью и ручные проверки. Фазы 03 и 05 можно вести параллельно с 02–04 в отдельных git-ветках или worktree, но не в одном рабочем дереве.

## Правила, которые экономят время

- Одна фаза — одна сессия. Если контекст разросся, `/compact`.
- Агент пошёл не туда: `/undo`, уточни формулировку, повтори. Коммиты после фаз служат точками отката.
- Правила меняй в файлах, а не в чате: правь SPEC, DESIGN или AGENTS и коммить. Чат агент забывает, файлы нет.
- Баг: `@prompts/_bugfix.md` с заполненными полями.
- Читай диффы сам. Особенно внимательно: слоты и гонки (05), доступ баристы (05, 07), всё, что касается денег.
- Секреты в чат не вставляй. `.env` в `.gitignore`.

## Что подставить, когда придёт от клиента

- **Логотип SVG** → `design/assets/logo-b.svg` (с `fill="currentColor"`), затем попроси агента обновить `Logo` и иконки PWA.
- **Цвет меди из брендбука** → `--copper` в `design/tokens.css`, затем «синхронизируй `web/` с `design/tokens.css`». В `tokens.css` цвета подобраны на глаз со скриншота.
- **Меню, цены, точки, часы** → `backend/seed/menu.yaml` (появится в фазе 02), затем `make reset-demo`.
- **Фото напитков** → дизайн держится на них. Пока их нет, стоят рисованные заглушки. Требования к съёмке в `docs/DESIGN.md`, раздел 5. Фото кладутся в `image_url` продукта.

## Если что-то не работает

- opencode не видит правил: запускай из корня, где лежит `AGENTS.md`.
- Агент нарушает границы фазы: напомни «Границы: … не делай» и попроси откатить лишнее (`/undo`).
- Сомневаешься в решении агента: попроси показать 2 варианта с плюсами и минусами до того, как он пишет код.
