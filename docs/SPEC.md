# SPEC — Balance

## 1. Цель и границы

**Цель.** Демо-MVP для презентации клиенту: клиент заказывает кофе на телефоне, заказ сразу появляется у баристы на планшете, статус обновляется у клиента в реальном времени.

**Платформа.** PWA (веб-приложение, ставится на экран телефона). Один API, позже к нему можно добавить Telegram Mini App.

**Входит в демо-MVP:** выбор точки, меню, кастомизация напитка, корзина, время готовности, заказ гостем, статус в реальном времени, экран баристы со стоп-листом, повтор последнего заказа.

**Не входит:** онлайн-оплата, полноценные аккаунты, админка (меню заливается из `backend/seed/menu.yaml`), push, промокоды, интеграция с кассой, аналитика. Бонусы входят в упрощённом виде (раздел 10).

## 2. Роли
- **Клиент** — гость без регистрации (имя + телефон).
- **Бариста** — вход по PIN точки; видит и меняет только заказы своей точки.
- **Админ** — в MVP работает через seed-файл и БД.

## 3. Сценарии

### Клиент
- C1. Открыть приложение, выбрать точку (последний выбор запоминается).
- C2. Смотреть меню по категориям; напитки из стоп-листа видны, но недоступны.
- C3. Открыть напиток, собрать состав: размер, молоко, сиропы, доп. шот и т.д. Цена меняется сразу.
- C4. Добавить в заказ. Корзина и оформление — один экран: там же изменить количество, удалить позицию, оставить комментарий.
- C5. Выбрать режим: «Сейчас» (как можно скорее, с оценкой времени) или «На время» (слот).
- C6. Оформить заказ: имя, телефон. Оплата при получении.
- C7. Смотреть статус заказа в реальном времени; отменить, пока заказ не принят в работу.
- C8. «Повторить последний заказ» с главного экрана (проверяет актуальную доступность).

### Бариста
- B1. Войти: точка + PIN.
- B2. Видеть очередь заказов в реальном времени; новый заказ подсвечивается и звучит.
- B3. Переводить заказ по статусам одним нажатием.
- B4. Управлять стоп-листом напитков и опций своей точки.

## 4. Доменная модель

| Сущность | Ключевые поля |
|---|---|
| Location | id, code (короткий, для номера заказа), name, address, timezone, opening_hours (по дням недели), lead_time_min (по умолчанию 10), slot_step_min (15), slot_capacity (единиц приготовления на слот, по умолчанию 6), staff_pin_hash, is_active |
| Category | id, slug, name, sort |
| Product | id, category_id, slug, name, description, base_price, image_url (может быть пустым), video_url (пусто в MVP), tags (например `no_caffeine`, `vegan`), prep_units (нагрузка на слот, по умолчанию 1), is_active |
| OptionGroup | id, key (`size`, `milk`, `syrup`, `shot`, `temperature`), name, min_select, max_select |
| ProductOptionGroup | product_id, group_id, sort, default_option_ids, при необходимости переопределяет min/max |
| Option | id, group_id, name, price_delta (может быть отрицательной), sort, visual (подсказка для отрисовки чашки, например `{"liquid":"oat"}`) |
| LocationProductAvailability | location_id, product_id, is_available. Нет строки = доступно |
| LocationOptionAvailability | location_id, option_id, is_available. Нет строки = доступно |
| Order | id, code (например `TV-042`, счётчик по точке за день), location_id, status, customer_name, customer_phone, comment, pickup_at (UTC), is_asap, total, currency, payment_method (`cash_on_pickup`), idempotency_key (уникален), access_token, created_at |
| OrderItem | order_id, product_id, product_name, quantity, unit_price, options (снапшот: список `{group, option, price_delta}`), line_total |
| SlotLoad | location_id, slot_start, units_reserved. Уникальность (location_id, slot_start) |
| OrderStatusEvent | order_id, from_status, to_status, at, actor (`customer`/`staff`/`system`) |

`group.min_select ≥ 1` — группа обязательна. Если `max_select = 1`, интерфейс показывает выбор одного варианта, иначе — множественный выбор.

## 5. Бизнес-правила

### 5.1 Цена
`unit_price = product.base_price + сумма(price_delta выбранных опций)`; `line_total = unit_price × quantity`; `total = сумма(line_total)`. Цена не может быть отрицательной. Считает сервер (`PriceCalculator`). Клиентский предпросчёт использует тот же алгоритм и обязан давать тот же результат.

### 5.2 Валидация выбора
Для каждой позиции: продукт активен и доступен на точке; опции принадлежат группам этого продукта; в каждой группе число выбранных опций между `min_select` и `max_select`; опции доступны на точке; `quantity` от 1 до 10; в заказе не больше 20 единиц.

### 5.3 Доступность (стоп-лист)
Строка `is_available = false` для точки скрывает вариант из выбора. В ответе меню недоступные продукты и опции возвращаются с `available: false`, чтобы интерфейс показал «Закончилось». Создание заказа с недоступной позицией отклоняется с `product_unavailable` или `option_unavailable`.

### 5.4 Слоты и вместимость
- Слот — начало интервала приготовления, выровнено по `slot_step_min` в часовом поясе точки.
- Слот доступен, если одновременно: (а) он не раньше `now + lead_time_min`, округлённого вверх до шага; (б) попадает в рабочие часы точки, причём не позже закрытия; (в) `units_reserved + units_заказа ≤ slot_capacity`.
- В MVP выбор — только на сегодня. Если точка сегодня закрыта или слотов нет, интерфейс говорит об этом прямо.
- `units_заказа = сумма(quantity × product.prep_units)`. Если `units_заказа > slot_capacity`, ошибка `order_too_large`.
- «Сейчас» (как можно скорее) = первый доступный слот. Пользователю показывается время этого слота.
- Резервирование происходит в той же транзакции, что и создание заказа, с блокировкой строки `SlotLoad` (`SELECT … FOR UPDATE` или `INSERT … ON CONFLICT` + блокировка). Два параллельных заказа не должны превысить вместимость.
- Отмена заказа освобождает вместимость слота.

### 5.5 Статусы заказа
`confirmed → preparing → ready → picked_up`, а также `cancelled`.

| Из | В | Кто |
|---|---|---|
| confirmed | preparing | staff |
| preparing | ready | staff |
| ready | picked_up | staff |
| confirmed | cancelled | customer, staff |
| preparing | cancelled | staff |

Прочие переходы запрещены (`invalid_transition`). Каждый переход пишет `OrderStatusEvent` и публикует событие в шину. Статус `pending_payment` зарезервирован для будущей онлайн-оплаты и в MVP не используется: заказ создаётся сразу в `confirmed`.

### 5.6 Идемпотентность
`POST /orders` требует заголовок `Idempotency-Key`. Повтор с тем же ключом и тем же телом возвращает уже созданный заказ. Тот же ключ с другим телом — ошибка `idempotency_conflict`.

### 5.7 Доступ гостя к заказу
При создании заказа выдаётся `access_token` (случайная строка ≥ 32 байт). Просмотр, SSE и отмена заказа требуют этот токен. Без него заказ недоступен.

### 5.8 Доступ баристы
`POST /staff/login {location_id, pin}` возвращает короткоживущий токен (например, 12 часов), привязанный к точке. Все staff-эндпоинты проверяют токен и точку. PIN хранится хешем; ограничение попыток входа.

## 6. API (черновик контракта)

Все ответы JSON. Ошибки: `{code, message, details}`. Коды: `validation_error`, `product_unavailable`, `option_unavailable`, `slot_unavailable`, `outside_hours`, `order_too_large`, `idempotency_conflict`, `invalid_transition`, `not_found`, `unauthorized`.

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Проверка живости |
| `GET /locations` | Список точек с признаком «открыта сейчас» |
| `GET /locations/{id}/menu` | Категории, продукты, группы опций, опции, доступность |
| `POST /locations/{id}/quote` | Валидация корзины и расчёт цены без сохранения |
| `GET /locations/{id}/slots?units=N` | Слоты на сегодня и оценка для «как можно скорее» |
| `POST /orders` | Создать заказ (`Idempotency-Key`). Ответ: заказ и `access_token` |
| `GET /orders/{id}` | Заказ (токен) |
| `GET /orders/{id}/events` | SSE-поток статуса (токен) |
| `POST /orders/{id}/cancel` | Отмена клиентом (токен) |
| `POST /staff/login` | Вход баристы |
| `GET /staff/orders` | Активные заказы точки |
| `GET /staff/orders/stream` | SSE: новые заказы и смены статуса |
| `POST /staff/orders/{id}/status` | Сменить статус |
| `GET /staff/availability` | Стоп-лист точки |
| `PUT /staff/availability/products/{id}` и `.../options/{id}` | Включить или выключить позицию |

SSE: клиент автоматически переподключается; при потере связи фронт опрашивает `GET /orders/{id}` как запасной вариант. Шина событий — за интерфейсом `EventBus`; в MVP реализация в памяти процесса (один воркер), позже Redis.

## 7. Нефункциональные требования
- Mobile-first, тёмная тема (светлая «сливочная» панель только на оформлении), i18n-ready (тексты в словаре), доступность (WCAG AA для текста).
- Первая загрузка на мобильной сети быстрая: код разделён по маршрутам, экран баристы не грузится клиентам.
- Персональные данные минимальны: имя и телефон; в логи не попадают.
- Валюта и формат денег задаются конфигом (`DEFAULT_CURRENCY`), отображение через `Intl.NumberFormat`.
- Наблюдаемость: структурные логи, `request_id` в каждом ответе.

## 8. Вне MVP (дорожная карта)
Онлайн-оплата (`PaymentProvider`), аккаунты и история заказов на сервере, админка меню с загрузкой фото, push-уведомления, лояльность и промокоды, заказ на другие дни, Telegram Mini App, интеграция с кассой, аналитика.

## 9. Открытые вопросы к клиенту
1. Страна и валюта; когда нужна онлайн-оплата и какой провайдер.
2. Реальные меню, цены, составы, доступные опции и молоко.
3. Адреса точек, часы работы, реальная пропускная способность.
4. Логотип в SVG, брендбук, фото напитков.
5. Нужны ли клиентам аккаунты и накопительная программа.
6. Языки интерфейса.

## 10. Дополнения после дизайна v2

Дизайн (`docs/DESIGN.md`) добавил три возможности. Они входят в демо-MVP и дополняют разделы выше.

### 10.1 Режим заказа
Поле `Order.mode`: `on_site` («На месте», человек уже в кофейне или у стойки, готовим сразу, `is_asap = true`, оценка ~N минут) и `scheduled` («На время»: слот из 5.4; чип «Скорее» = первый доступный слот). Слот резервируется в обоих режимах, чтобы нагрузка учитывалась.

### 10.2 Ролики приготовления
Поля `Product`: `video_url`, `poster_url`, `video_duration_sec`, `video_steps` (JSON: подписи и времена шагов). Все поля необязательные; без них интерфейс показывает рисованную анимацию. Файлы отдаёт статика или CDN; в MVP лежат в `web/public/media`. Требования к файлам: DESIGN, раздел 8.

### 10.3 Бонусы (упрощённо)
- Сущности: `BonusAccount` (phone, balance, lifetime_spent, level), `BonusTransaction` (account_id, type: `accrual` | `redeem` | `adjust`, amount, order_id, created_at).
- Начисление: 5% от оплаченной суммы, округление вниз, при переходе заказа в `picked_up`. Процент и пороги уровней — в конфиге.
- Списание: 1 балл = 1 единица валюты, не более 50% суммы заказа. `POST /orders` принимает `use_bonus_points`; сервер сам проверяет баланс и ограничение и возвращает `bonus_applied` в котировке и заказе. `total` уже учитывает скидку.
- Уровни: «Эспрессо», «Латте», «Баланс» (пороги по накопленным тратам, в конфиге).
- Идентификация в демо: по номеру телефона и токену гостя, выданному при первом заказе. Без SMS-подтверждения, поэтому баллы демо не считаются защищённой ценностью. В полной версии: вход по SMS-коду.
- API: `GET /bonus/account`, `GET /bonus/transactions` (по токену гостя).
- Отмена заказа возвращает списанные баллы и не начисляет новые.
